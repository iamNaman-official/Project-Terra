# Documentation

Documentation for knowledge, discoveries, datasets, experiments, architecture, and project decisions.

## Structure

- `learning/` — Concepts the team learns
- `datasets/` — Dataset documentation
- `experiments/` — Results and conclusions from experiments
- `architecture/` — System and software architecture
- `notes/` — General technical notes and observations

## Principle

If the team learns something important, write it down.

Documentation should make it possible for another team member to understand:

- What was tried
- Why it was tried
- What happened
- What was learned
- What should happen next
